# T61 浏览器面板（共享 Chrome + bw 双客户端）设计基线

> 状态：草稿
> 级别：大（新子系统、跨 main/renderer/contracts 三层、并发与安全面齐备）
> 前置实证：/tmp/spike 三轮 spike 已验证核心命题（2026-10-13，结论见 §12）

## 1. 目标与非目标

### 处理什么

1. **应用内浏览器面板**（panel kind `'browser'`）：投屏画布 + tab 条 + 地址栏 + attach 命令复制条，人可直接浏览与操作（输入转发）。
2. **Agent 用 bw 操作同一浏览器**：面板 Chrome 暴露稳定 CDP 端口，Agent 在 worker 内跑 `bw s create --cdp-url` attach，与面板共存（双客户端，spike 实证无冲突）。
3. **元素拾取进对话**：拾取模式圈选页面元素 → 结构化描述（选择器/aria 路径/computed style/outerHTML 片段）+ 按元素 bbox 裁剪的截图 → 以现有 image+text 输入形态进输入区。
4. **Agent 动作可视化**：事件钩子（capture-phase listener + Runtime.addBinding）统一观测人/Agent 两侧输入事件 → 面板涟漪/滚动指示 + 动作时间线。
5. **确认门桥接**：bw `CONFIRMATION_REQUIRED` + `cid` → X3code confirm 对话框，用户批准后回 `bw s confirm <sid> <cid> --yes`。
6. **调试 drawer**：`bw s console/errors/requests/perf` 结果面板化（Console/Network/Perf 三 tab）。
7. **测试网站工作流**：localhost 直达（`--allow-private-network`）、视口预设双向同步、Agent 验证截图自动进对话。

### 不处理什么（写清归属）

| 项 | 归属 |
| --- | --- |
| 网络节流/弱网模拟、请求 mock/拦截、触屏模拟 | bw 明示不支持；逃生门 = `bw s create --debug-port 0` + 真 DevTools（用户手动） |
| x-harness 侧任何改动（工具化 bw、协议扩展） | 旁级仓库不在本仓修改范围；Agent 会用 bw 靠 prompt 侧（AGENTS.md/skill 文档） |
| GPU 合成动画页面的连续投屏帧 | headless 无合成器心跳，screencast 事件驱动不产帧（已知限制）；Agent 复核用 `bw s look` 不受影响；记录于面板文案 |
| 移动端（apps/mobile）浏览器面板 | 本任务桌面端 only |
| 与本机日常 Chrome 共享登录态 | `bw auth import-chrome` 单站导入是既有能力，用户手动执行；面板不做自动同步 |
| Electron `<webview>` 方案 | 已裁决否决（见 §11 裁决 D1）：bw 无法驱动 webview guest，且 zcode 实证的平台坑成本高 |

## 2. 架构总览

```
┌─ 渲染层（apps/electron/src/renderer/src/browser/）─────────────┐
│ BrowserPanel（panel kind 'browser'，singleton tab）              │
│   ├ 投屏画布（JPEG 帧绘制 + 视口缩放 transform）                 │
│   ├ tab 条 / 地址栏（normalize + scheme 白名单）/ attach 复制条  │
│   ├ 拾取模式层 / 动作涟漪层 / 虚拟光标                            │
│   └ 调试 drawer（Console / Network / Perf）+ 动作时间线          │
└────────┬──────────────────────────────────▲───────────────────┘
    invoke 'browser/*'              subscribe 'browser/event'
┌────────▼──────────────────────────────────┴───────────────────┐
│ 主进程（apps/electron/src/main/browser-host/）                   │
│  chrome-supervisor：spawn/心跳(ws ping)/挂死重启/僵尸收养/停机    │
│  cdp-client：screencast(ack) + 输入转发 + 事件钩子 + tab 表       │
│  browser-routes：ApiSchemas 校验的 invoke 路由 + 事件推送         │
└────────┬───────────────────────────────────────────────────────┘
         │ CDP ws（127.0.0.1:stablePort，双客户端共存）
         ├──────── 我方 cdp-client（投屏/输入/观测）
         └──────── Agent 的 bw attach（worker 内 CLI 调用）
                    ▲ X3CODE_BROWSER_CDP env（spawn-env 白名单注入）
                    ▼
         Chrome headless（应用级 user-data-dir，7×24 常驻）
```

关键机制（spike 实证编号见 §12）：

- **S1 稳定端口**：应用启动时从空闲池分配端口写入主进程内存态 + `X3CODE_BROWSER_CDP` env；Chrome 重启（崩溃/监督重启）绑回同端口。Agent 的 bw 会话跨 Chrome 重启存活（端口不变即可重连，bw 的 BROWSER_DEAD 自动恢复路径）。
- **S2 screencast ack 循环**：每帧回 `Page.screencastFrameAck`；帧语义为变化驱动（交互 16ms 出帧、静止 1 帧基线），静止页无 CPU 消耗。
- **S3 事件钩子**：`Page.addScriptToEvaluateOnNewDocument` 注入 capture-phase listener + `Runtime.addBinding('__x3bReport')` 回传；人的转发输入与 Agent 的 bw 输入**统一来源**，动作时间线不区分产生者（面板涟漪同源）。
- **S4 双客户端**：bw attach 收养既有 tab，opentab 开新 target；我方 browser-level ws 经 `Target.setDiscoverTargets` 观察 target 增删，tab 条与之同步。
- **S5 确认门**：Agent 的 bw 命令 stdout JSON 携 `cid` 时（CONFIRMATION_REQUIRED），worker 无法自证用户批准——**该桥接的真相源是渲染层 confirm 对话框**；主进程提供 `browser/confirmGateway` 通道把 cid 转发给 Agent 侧（M3 细化：经 hub ui_request 或面板内嵌对话框，二选一，见施工图）。

## 3. 契约

### 3.1 IPC 通道（packages/contracts 新增 `browser-api.ts`，挂进 ApiSchemas）

invoke（渲染层 → 主进程）：

| 方法 | 参数 | 结果 |
| --- | --- | --- |
| `browser/bootstrap` | `{}` | `{ status, cdpEndpoint, chromePath, tabs, activeTargetId, viewport }` |
| `browser/navigate` | `{ targetId, url }` | `{ ok: true } \| { ok: false, reason }`（URL 归一化 + scheme 白名单在主进程） |
| `browser/input` | `{ targetId, kind, ... }` | `{ ok: true }`（kind: mouse/wheel/key/insertText；IME 走 insertText） |
| `browser/tabOpen` / `browser/tabClose` / `browser/tabActivate` | `{ targetId? , url? }` | `{ targetId }` / `{ ok }` |
| `browser/viewportSet` | `{ targetId, width, height, preset? }` | `{ ok }`（`Emulation.setDeviceMetricsOverride`） |
| `browser/pickElement` | `{ targetId, x, y }` | `{ element: PickedElement, shotB64 }`（结构化解析 + bbox 裁剪图） |
| `browser/debugQuery` | `{ targetId, source: 'console'\|'errors'\|'requests'\|'perf' }` | 结构化行数组（数据来自主进程对 bw CLI 的调用或直接 CDP，M4 细化） |
| `browser/confirmGateway` | `{ cid, approve }` | `{ ok }`（确认门桥接，M3） |

subscribe（主进程 → 渲染层，`browser/event` 帧）：

| 事件 | 载荷 |
| --- | --- |
| `frame` | `{ targetId, jpegB64, metadata? }`（screencast 帧，含 devicePixelRatio/scale） |
| `tabsChanged` | `{ tabs: [{ targetId, url, title, active }] }` |
| `action` | `{ targetId, kind: 'click'\|'input'\|'change'\|'keydown'\|'scroll', x?, y?, el?, y? }`（S3 钩子回传，统一人/Agent） |
| `navState` | `{ targetId, url, canBack, canForward, loading }` |
| `hostState` | `{ phase: 'starting'\|'ready'\|'restarting'\|'failed', cdpEndpoint? }` |
| `confirmRequest` | `{ cid, reason, sessionId? }`（M3 确认门） |

**zod schema 全量落在 `packages/contracts/src/browser-api.ts`**（单一真相），错误形态沿用 `{ ok: false, reason }` 判别联合；事件帧走既有 subscribe 面（preload 四面不变）。

### 3.2 PickedElement 形状

```ts
type PickedElement = {
  tag: string; id?: string; classes: string[];
  ariaLabel?: string; textPreview: string;        // ≤120 chars，敏感值过滤后
  selector: string;                               // 生成式 CSS 选择器（id 优先 → nth-of-type 兜底）
  styles: { fontSize, color, backgroundColor, margin, padding, display };  // 样式问题定位核心子集
  outerHtml: string;                              // 截断 ≤2KB，敏感属性值脱敏
  cdpEndpoint: string;                            // Agent 接入点（随卡片自动携带）
  pageUrl: string;
};
```

敏感过滤规则（M2 测试口径）：`password/token/secret/key/authorization` 命中属性名或 URL query 的值替换为 `***`。

### 3.3 env 注入

`packages/infra/src/host-process/spawn-env.ts` 白名单追加 `X3CODE_BROWSER_CDP`（值 `http://127.0.0.1:<stablePort>`）。Agent worker 环境可直接读；面板 attach 复制条文本同源生成。

## 4. 安全设计

| 面 | 措施 |
| --- | --- |
| CDP 端口暴露面 | 绑 127.0.0.1；本机恶意进程可连（与 dev server 同信任级，威胁模型文档明示）；`--remote-allow-origins` 收紧实测（M1 任务，若 bw 兼容则启用） |
| URL 治理 | 地址栏输入归一化（无协议智能补 http/https，localhost/私网补 http）；scheme 白名单 `http/https/about/data`（file:// 拒绝，与 bw POLICY_BLOCKED 对齐） |
| 确认门映射 | localhost/127.0.0.1/已批准域（session 记忆）→ 自动确认；新域/敏感词（S2 门）→ 弹 confirm 对话框；拒绝后 bw 命令收到 CONFIRMATION_DENIED |
| 输入面 | `browser/input` 仅接受渲染层合法坐标（画布内）；无任意 JS 执行通道（eval 能力只在 bw 侧由其自身门控管理） |
| 元素拾取数据卫生 | §3.2 敏感过滤；密码框值源头打码（bw 已做，我方二次防御：input[type=password] 的 value 恒 `***`） |
| profile 数据 | `userData/browser-profile`（0700）；「清除浏览数据」设置项 = 删目录 + 重启 Chrome；威胁模型明示 cookie 明文存于本目录（Chrome 自管，无法加密整目录） |
| Electron 安全面零变化 | 不开 webviewTag、不动 webPreferences、CSP 不变（投屏画布是纯 img/canvas，无网页内容进渲染层） |

## 5. 生命周期与监督

- **chrome-supervisor**（薄监督器，参考 infra/host-process 模式但不复用代码）：spawn → ws ping 心跳（2s 间隔，3 失败判死）→ 重启绑回稳定端口 → 僵尸收养（pidfile：活着且端口可连 = 收养；死了 = 清 user-data-dir 锁重启）。
- **Chrome 常驻策略**：面板关 = 只停投屏（stopScreencast），Chrome 存续（Agent 的 bw 会话不中断）；应用退出（`will-quit`）= Chrome 退出（优雅 SIGTERM → 3s 后 SIGKILL）。
- **僵尸清理**：应用崩溃残留 Chrome 占 user-data-dir 锁 → 启动时 pidfile 探测处理（同上）。
- **会话纪律**（Agent prompt 侧 + 错误文案）：SESSION_LIMIT(16) → 先 close 旧会话；SESSION_BUSY → 串行重试；BROWSER_DEAD → 直接重试（端口不变）。

## 5a. 并发/一致性预算

| 项 | 预算 |
| --- | --- |
| 投屏帧延迟 | 交互 → 面板出帧 P95 < 100ms；Agent bw 动作 → 面板可见 < 200ms（事件钩子路径） |
| 帧带宽 | JPEG quality 50 / maxWidth 1286（面板 CSS 尺寸 × dpr）；静止页 0 帧开销 |
| screencast 并发 | 每 target 1 路（active tab 才开）；后台 tab 停流 |
| CDP 命令 | 主进程客户端串行队列（每 target 一个 mutation 队列，防 viewport/输入交错） |
| 动作事件 | binding 回传 ≤ 20 事件/s 节流（scroll 高频合并）；时间线环形缓冲 200 条 |
| Chrome 重启恢复 | < 3s（kill -9 → supervisor 检测 → 重启 → 端口复用 → tab 恢复导航栈） |
| 内存 | 投屏解码画布单 tab ≤ 30MB（JPEG 帧不缓存历史，仅当前帧 + 下一帧双缓冲） |

1. 用户 dev server 跑着（Vite :5173）→ 面板地址栏输入 `localhost:5173` → 自动补 http → 直达

## 11. 裁决记录

| # | 裁决 | 依据 |
| --- | --- | --- |
| D1 | `<webview>` 方案否决，用共享 Chrome + 投屏 | 用户需求「Agent 用 bw 操作」——bw 只能 attach 独立 Chromium 进程；webview guest 无调试端口。zcode 的 webview 方案与 bw 不兼容（其 agent 走自建 CDP broker） |
| D2 | headless + 应用内投屏（非 headed 真窗口） | 面板是唯一视觉出口，「人看 Agent 操作」免费获得；bw 日常形态成熟。代价（无原生文本选择/动画不产帧）已列入已知限制 |
| D3 | Chrome 应用级单实例（非 per-thread） | 简单直接，tab 即 target；多会话各自浏览器翻倍登录态/内存——留待真实需求 |
| D4 | Chrome 常驻（面板关不退），应用退出才退 | Agent 任务跨面板开合不能断；bw 会话 30min GC 自愈 |
| D5 | 确认门走面板内嵌对话框 + confirmGateway（非 hub ui_request） | hub 协议零改动；x-harness 是旁级仓库不可改。**用户裁决**：全都要的范围内按零协议改动优先 |
| D6 | 稳定端口策略（重启绑回） | Chrome 重启不孤儿化 Agent 的 bw 会话（spike SESSION_LIMIT 教训 + BROWSER_DEAD 恢复路径依赖端口不变） |
| D7 | Chrome 二进制发现序：设置覆盖 > BUN_CHROME_PATH > 标准探测 > 引导态 | 不打包 Chromium（+150MB/许可/签名）；探测失败给引导 UI 而非硬失败 |
| D8 | profile 持久于 userData/browser-profile（0700） | 登录态可复用；明文 cookie 风险进威胁模型文档 + 「清除浏览数据」设置项 |

（D2/D3/D4/D7/D8 为默认裁决，已在上一轮讨论给否决窗口；D1/D5/D6 为本轮新增裁决，随本方案再给否决窗口——定稿前可改。）

## 13. 风险与开放问题

| 风险 | 缓解 |
