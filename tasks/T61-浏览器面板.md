# T61 浏览器面板（共享 Chrome + bw 双客户端）设计基线

> 状态：草稿（对抗审查三路已并入：安全面 9 条 / 生命周期面 13 条 / 契约并发面 23 条，处置见 §14）
> 级别：大（新子系统、跨 main/renderer/contracts 三层、并发与安全面齐备）
> 前置实证：/tmp/spike 三轮 spike + C8 链路实证（2026-10-13，见 §12）

## 1. 目标与非目标

### 处理什么

1. **应用内浏览器面板**（panel kind `'browser'`）：投屏画布 + tab 条 + 地址栏 + attach 复制条，人可直接浏览与操作（输入转发）。
2. **Agent 用 bw 操作同一浏览器**：面板 Chrome 暴露 CDP 端口，Agent 在 worker 内跑 `bw s create --cdp-url` attach，与面板共存（双客户端，spike 实证无冲突）。
3. **元素拾取进对话**：拾取模式圈选页面元素 → 结构化描述 + 按元素 bbox 裁剪的截图 → 以现有 image+text 输入形态进输入区。
4. **Agent 动作可视化**：事件钩子（capture-phase listener + Runtime.addBinding）统一观测人/Agent 两侧输入事件 → 面板涟漪/滚动指示 + 动作时间线。
5. **确认门桥接（协作 UX 层，非安全边界——见 §4a）**：bw `CONFIRMATION_REQUIRED` + `cid` → 面板通知（时间线高亮 + 可选对话框），用户批准后经 `browser/confirm` 回 `bw s confirm <sid> <cid> --yes`。
6. **调试 drawer**：`bw s console/errors/requests/perf` 结果面板化（Console/Network/Perf 三 tab）。
7. **测试网站工作流**：localhost 直达（`--allow-private-network`）、视口预设双向同步、Agent 验证截图自动进对话。

### 不处理什么（写清归属）

| 项 | 归属 |
| --- | --- |
| 网络节流/弱网模拟、请求 mock/拦截、触屏模拟 | bw 明示不支持；逃生门 = `bw s create --debug-port 0` + 真 DevTools（用户手动） |
| x-harness 侧任何改动 | 旁级仓库不改；**C8 实证：hub workerEnv 是父 env 全量透传（host.ts:116-125），本仓白名单放行即通，无需 x-harness 改动** |
| GPU 合成动画页面的连续投屏帧 | headless 无合成器心跳（已知限制）；Agent 复核用 `bw s look`；面板提示文案 |
| 移动端浏览器面板 | 桌面端 only |
| 与本机日常 Chrome 共享登录态 | `bw auth import-chrome` 用户手动；不自动同步 |
| Electron `<webview>` 方案 | 裁决否决（D1）：bw 无法驱动 webview guest |
| 多 Agent 并发仲裁（tab 互踩的锁/租约） | 临时 profile 下互踩只是打架不是泄漏；M1 集成测试钉住行为面，仲裁留待真实需求 |

## 2. 架构总览

```
┌─ 渲染层（apps/electron/src/renderer/src/browser/）─────────────┐
│ BrowserPanel（panel kind 'browser'，singleton tab）              │
│   ├ 投屏画布（JPEG 帧绘制 + 视口缩放 transform）                 │
│   ├ tab 条 / 地址栏（normalize + scheme 白名单）/ attach 复制条  │
│   ├ 拾取模式层 / 动作涟漪层 / 虚拟光标 / IME 输入浮层            │
│   └ 调试 drawer（Console / Network / Perf）+ 动作时间线          │
└────────┬──────────────────────────────────▲───────────────────┘
    invoke 'browser/*'              subscribe 'x3code:browser-event'
┌────────▼──────────────────────────────────┴───────────────────┐
│ 主进程（apps/electron/src/main/browser-host/）                   │
│  chrome-supervisor：spawn/双探心跳/挂死重启/残留清理/进程组停机  │
│  cdp-client：screencast(ack 旁路) + 输入转发 + 事件钩子 + tab 表 │
│  browser-routes：ApiSchemas 校验的 invoke 路由 + 事件推送         │
└────────┬───────────────────────────────────────────────────────┘
         │ CDP ws（127.0.0.1，端口持久化于 browser-host.json）
         ├──────── 我方 cdp-client（投屏/输入/观测）
         └──────── Agent 的 bw attach（worker 内 CLI）
                    ▲ X3CODE_BROWSER_CDP + BW_HOME env（spawn-env 白名单）
                    ▼
         Chrome headless（默认临时 profile；持久登录态 opt-in）
```

关键机制：

- **S1 端口持久化**：端口写入 `userData/browser-host.json`（原子写：临时文件 + rename）。应用启动时读取；端口被占则三重验证（占主 pid 存活 + 命令行含本 userData 的 browser-profile 路径 + CDP `/json/version` 可连）→ 是残留 Chrome 则进程组击杀 → 轮询等退净（≤5s）→ 清 SingletonLock → 正常 spawn。**不存在跨应用收养**（旧应用的渲染层会话已死，收养无意义）。
- **S2 screencast**：ack 旁路（不进串行队列）；停流时在途迟到帧丢弃不 ack（Chrome 视会话结束，复流为新世代）；同 target 停/复流用世代号（帧载荷带 `streamEpoch`），旧世代帧渲染层直接丢。
- **S3 事件钩子**：`addScriptToEvaluateOnNewDocument` capture-phase listener + `Runtime.addBinding('__x3bReport')`；**回传载荷按敌意输入处理**（原型链键剥离、长度上限 2KB、节流 20/s）——页面 JS 可伪造 action 事件（时间线污染属 UX 风险，无安全后果：时间线不驱动任何授权决策）。
- **S4 双客户端**：我方 browser-level ws 经 `Target.setDiscoverTargets` 观察 target 增删；**tab 激活真相源 = 主进程**（bw 侧激活无 browser 级事件，主进程在收到任何 tabs 查询/操作后主动 `Target.getTargets` + per-target `Runtime.evaluate(document.hasFocus())` 采样对齐）。
- **S5 确认门（UX 层）**：cid 由 Agent 经对话流自报（消息文本携 `bw-confirm://cid` 标记）或面板时间线轮询 bw 会话状态；面板通知用户 → 批准后主进程代跑 `bw s confirm`（主进程作为 bw CLI 的另一个客户端，会话文件在 BW_HOME 命名空间内可寻址）。
- **S6 懒启动**：Chrome 不随应用启动——首个 `browser/*` invoke（面板首次打开）才 spawn；`X3CODE_BROWSER_CDP` env 在应用启动时即定（读 browser-host.json，无则分配+持久化），与 Chrome 实际 spawn 解耦。

## 3. 契约

### 3.1 invoke 通道（contracts 新增 `browser-api.ts` 挂进 ApiSchemas；错误形态一律走传输层 ApiError，kind 闭集，无双层 ok、无裸 reason）

| 方法 | params（strict zod） | result（失败走 ApiError） |
| --- | --- | --- |
| `browser/bootstrap` | `{}` | `{ status, cdpEndpoint?, chromePath?, chromeMissing? , tabs, activeTargetId?, viewport?, navStates }`——starting/chromeMissing 态字段可空（zod 可选） |
| `browser/navigate` | `{ targetId, url }` | `{ url }`（归一化 + scheme 白名单失败 → `invalid_url`） |
| `browser/input` | `{ targetId, input: InputEvent }` | `void`；target 已死 → `target_gone` |
| `browser/tabOpen` | `{ url? , targetId? }` | `{ targetId }`（url 开新；targetId 参数 = 复制语义，M1 不实现则删） |
| `browser/tabClose` | `{ targetId }` | `void`；target 已消亡幂等成功 |
| `browser/tabActivate` | `{ targetId }` | `void`；不存在 → `unknown_target` |
| `browser/viewportSet` | `{ targetId, width, height, preset? }` | `void`；crashed → `target_gone` |
| `browser/pickElement` | `{ targetId, x, y }`（页面 CSS 坐标） | `{ element: PickedElement, shotB64 }`；落空（空白/跨域 iframe）→ 降级返回最近可描述祖先或 `pick_miss` |
| `browser/debugQuery` | `{ targetId, source }` | `ConsoleRows \| ErrorRows \| RequestRows \| PerfSummary`（schema 全量落 contracts；数据源 = 主进程在 BW_HOME 下按 targetId↔bw 会话映射表调 bw CLI；映射缺失 → `no_bw_session`） |
| `browser/confirm` | `{ sid, cid, approve }` | `void`；bw 会话/确认不存在 → `confirm_gone` |

`InputEvent` 判别联合（kind）：

```ts
type InputEvent =
  | { kind: 'mouse'; x: number; y: number; button: 'left'|'right'|'middle'; press: boolean; clickCount?: number }
  | { kind: 'wheel'; x: number; y: number; deltaX: number; deltaY: number }
  | { kind: 'key'; key: string; modifiers?: string[] }          // keydown/keyup 由 press 序列表达
  | { kind: 'keySequence'; key: string; down: boolean }
  | { kind: 'insertText'; text: string };                        // IME 与普通文本注入统一路径
```

**坐标域**：页面 CSS 坐标（viewport 单位）。渲染层负责画布→页面换算（帧 metadata 携 `deviceWidth/deviceHeight/pageScaleFactor`，主进程从 CDP screencastFrame metadata 透传）。

### 3.2 PickedElement（补 bbox + frame 寻址；不带 cdpEndpoint——历史卡片带过期端口是缺陷，Agent 端点发现统一走 env 与面板复制条）

```ts
type PickedElement = {
  tag: string; id?: string; classes: string[];
  ariaLabel?: string; textPreview: string;        // ≤120 chars，脱敏后
  selector: string; frameId?: string;             // iframe 内元素：主文档上下文 selector 不可用，带 frameId 寻址
  bbox: { x: number; y: number; width: number; height: number };   // 页面 CSS 坐标（卡片标注框 + Agent 坐标重建）
  styles: { fontSize, color, backgroundColor, margin, padding, display };
  outerHtml: string;                              // 先脱敏后截断 ≤2KB
  pageUrl: string;
};
```

**脱敏规则（表驱动，M2 测试矩阵）**：属性名命中 `password/token/secret/key/auth/credential`（子串、大小写不敏感）→ 值 `***`；URL query **与 fragment** 键命中同表 → 值 `***`；文本内容按模式匹配（`sk-`、`ghp_`、`AKIA`、`Bearer `、长 base64 串）→ 截断替换；`input[type=password]` 的 value 恒 `***`；`value` 属性统一过文本模式扫描；**顺序 = 先脱敏后截断**。截图另列「像素级可能含敏感文本」为已知残留风险（文档明示，不做 OCR）。

### 3.3 env 注入（C8 链路已实证通）

`spawn-env.ts` 白名单追加 `X3CODE_BROWSER_CDP` 与 `BW_HOME`（值 `userData/browser-bw-home`）。hub workerEnv 全量透传（host.ts:116-125），worker 可读。端口一致性：**worker env 的端点 = 应用启动时定格**；Chrome 重启优先绑回该端口，被占（罕见：另一应用实例占同名端口——单实例锁已挡双开）则记 `hostState.portMoved` 事件，Agent 通过面板复制条重取。

### 3.4 事件通道

**独立 subscribe 面 `x3code:browser-event`**（preload 桥新增一个受控面；大 payload 帧与既有 `x3code:event` 流式通道隔离，避免投屏高频期拖慢会话渲染）。帧判别键 = 帧 `type` 字段（与载荷内业务字段不同名）；词表挂进 contracts 的封闭机制（`BROWSER_EVENT_TYPES` 双向断言，同 UI_EVENT_TYPES 模式）。

| type | 载荷（摘要） |
| --- | --- |
| `frame` | `{ targetId, streamEpoch, jpegB64, meta: { deviceWidth, deviceHeight, pageScaleFactor } }` |
| `tabsChanged` | `{ tabs: [{ targetId, url, title, active }] }`（active 真相源 = 主进程 S4） |
| `action` | `{ targetId, kind: 'click'\|'input'\|'change'\|'keydown'\|'scroll', x?, y?, elementLabel? }`（敌意输入防御见 S3） |
| `navState` | `{ targetId, url, canBack, canForward, loading }` |
| `viewportChanged` | `{ targetId, width, height }`（bw 侧改视口后主进程采样对齐） |
| `hostState` | `{ phase: 'starting'\|'ready'\|'restarting'\|'failed'\|'chromeMissing', cdpEndpoint?, detail? }`；**转移语义：ready 恰好一次/次；failed 自动重试一次后转 chromeMissing 或停机（非吸收态）；restarting 进出必配对**；restarting/failed 时渲染层作废全部 targetId、清空画布（陈旧帧契约） |
| `confirmNotice` | `{ sid, cid, reason }`（无终态配对要求：bw 侧 120s 超时自然失效，面板侧同样 120s 超时收起——超时值与 bw 对齐） |

bootstrap 兜底：`navStates` 全表进 bootstrap（渲染层重载后 canBack/canForward 可恢复）。

## 4. 安全设计（审查后重写：信任边界如实化）

**安全边界的三根柱**（按防御深度排序）：

1. **临时 profile（默认）**：每次应用启动全新 profile——CDP 端口被本机恶意进程利用时，可操作的登录态 ≈ 0（与「读任意本地文件/任意落盘」的本机既有攻击面同量级：能连 127.0.0.1 端口的恶意进程本就能干这些）。持久登录态 = 显式 opt-in 设置项（开启时 UI 明示：本机任意进程将可驱动该登录态）。
2. **port 不永续信任**：CDP 端口本身不设防（与 bw spawn 自有 Chrome 同暴露面）——威胁模型如实声明：**CDP 端口是本机全权控制通道，依赖本机进程全体可信**；不使用 `--remote-allow-origins`（永不设置——该 flag 放行的是网页来源的 ws 连接，bw 无 Origin 头不受影响，设置了反而开放给恶意页面）。
3. **用户可断**：面板「重置浏览器」按钮 = 杀 Chrome + 换新临时 profile + （opt-in 持久态时提示重新确认）。prompt injection 驱动 Agent 乱来的最坏情况，用户有一个动作级止血面。

**如实降级的声明**（不再称安全边界）：

- 确认门桥接 = 协作 UX（cid 由 Agent 自报，无法防 Agent 自 confirm；安全后果由柱 1/3 兜底）
- 坐标校验 = 防误触，不防攻陷渲染层（渲染层被 XSS 后本就能调任何 invoke 面；帧像素流入被攻陷渲染层属 Electron 既有威胁模型内的增量面，随临时 profile 弱化）
- 拾取脱敏 = 数据卫生（尽力而为的模式匹配，非密码学保证；截图像素残留风险文档明示）

**其余安全面**：

| 面 | 措施 |
| --- | --- |
| URL 治理 | 地址栏归一化 + scheme 白名单（http/https/about/data；file:// 拒绝）——只约束我方 navigate 通道 |
| 输入面 | `browser/input` 坐标域校验（数值范围）防垃圾输入，不称安全措施 |
| binding 回传 | 敌意输入处理（S3）：原型链剥离、2KB 上限、20/s 节流 |
| profile at-rest | 临时 profile 随应用退出删除；opt-in 持久 profile 的 cookie 加密性随 Chrome 版本（不承诺）；文档明示 Time Machine/同步盘重放风险 |
| Electron 配置 | 不开 webviewTag、不动 webPreferences——**但声明：这不是「安全面零变化」，是「攻击面转移」**（见上） |

## 5. 生命周期与监督

- **chrome-supervisor**：spawn（`detached: true` 进程组）→ 双探心跳（ws ping 每 2s；**连续 3 次 ws 失败后追加一次 HTTP `/json/version` 探测，双失败才判死**——容忍休眠时钟跳变：macOS 合盖 timer 冻结，唤醒后靠 HTTP 探测的活性确认避免误杀）→ 判死 → 进程组击杀（`kill(-pgid)`）→ 重启绑回持久化端口。**熔断**：连续 3 次启动失败（spawn 即退/10s 内 ws 不通）→ `chromeMissing`/`failed` 态 + 引导（区分 chromePath 二进制缺失 vs profile 损坏：前者给路径设置引导，后者给「重建 profile」——后者仅 opt-in 持久态会出现，临时 profile 每次全新不存在损坏积累）；失败计数在用户操作（改设置/确认重试）后显式清零。
- **残留清理**（应用启动时，S1）：三重验证残留 Chrome → 进程组击杀 → 等退净（≤5s 轮询）→ 清 SingletonLock → spawn。**主进程 `process.on('exit')` 同步击杀兜底**（防孤儿 Chrome）。
- **Chrome 常驻**：面板关 = 停投屏（停 ack 即停流），Chrome 存续；应用退出（`will-quit`）= SIGTERM 进程组 → 3s SIGKILL 兜底 + 临时 profile 目录删除。
- **Agent 会话纪律**（AGENTS.md + 错误文案）：任务完成即 `bw s close`；SESSION_LIMIT → close 旧会话；SESSION_BUSY → 串行重试；BROWSER_DEAD → 直接重试（端口不变）。**BW_HOME 注入使 bw 会话文件落本仓命名空间**（可枚举、可诊断、可批量清理——「应用退出后 bw 会话自然失效」不再依赖 30min idle GC（对持续重试的会话永不触发——L7 修正），改为主进程退出前尽力 close 已知会话）。
- **多 Agent 争用**：不仲裁（不处理表）；M1 集成测试钉「A 关 B 的 tab / 同 target 互写」的实际行为，作为已知交互记录。

## 5a. 并发/一致性预算（审查后修正）

| 项 | 预算 | 修正说明 |
| --- | --- | --- |
| 投屏帧延迟 | 交互 → 出帧 P95 < 100ms；Agent 动作 → 时间线可见 < 200ms | 时间线不依赖帧（钩子事件独立通道），Agent 在非活跃 tab 操作时**时间线照常、画面照旧**（不自动抢激活——C11 裁决） |
| 帧带宽 | JPEG q50 / maxWidth = 画布 CSS 宽 × dpr；面板不可见（panel 关/minimize）→ 停流 | 无应用层背压（如实声明）；高频页靠停流 + maxWidth 限流 |
| screencast | active target 单路；ack 旁路不进串行队列 | C10：ack 被慢命令阻塞会导致停帧 |
| CDP 命令 | 主进程 mutation 每 target 串行队列；**只串行主进程自身**，bw 是独立连接不受此队列约束（如实声明）；pickElement/debugQuery 读命令允许与 mutation 交错（读到中间态坐标 = 已知语义） | C9 边界如实化 |
| 动作事件 | ≤20/s 节流；环形缓冲 200 条；**渲染层重载后历史不恢复**（bootstrap 无历史快照，如实声明） | C23 |
| Chrome 重启 | kill -9 路径 < 5s 可交互（检测→击杀→重启→ready）；挂死路径 = 心跳窗口 6-8s + 重启；**tab 按 URL 恢复（session 表快照），back/forward 历史栈不恢复**（CDP 无注入 history API——已知限制） | L6：原 3s 含导航栈不可达 |
| 内存 | 单 tab 投屏 ≤ 30MB（当前帧 + 在途帧双缓冲） | |
